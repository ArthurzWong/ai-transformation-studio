# Blueprint → Feature Plan (Source of Truth Extraction)

Blueprint input: the pipeline diagram supplied by the user (message of 2026-09-19).
Every node/edge in that diagram is mapped below to a concrete, testable feature.
Nothing from the blueprint is dropped; additions required to make it a real app
(persistence, API, history) are listed separately as supporting features.

## 1. Blueprint element → feature mapping

| # | Blueprint element | Implemented feature | Where |
|---|---|---|---|
| B1 | **Human Strategist** (entry node, feeds orchestrator) | Strategist intake: transformation goal (required), industry/context, constraints, success criteria + 3 example briefs. Validation blocks empty goal. | `POST /api/runs` · UI Stage 1 panel |
| B2 | **Grok Bot — Orchestrator** | Orchestrator stage decomposes the strategist intent into a dispatch plan (plan summary persisted), dispatches the 3 tracks, arbitrates model selection. In live mode the plan is generated by the xAI Grok chat API; in demo mode by a goal-aware simulator. All orchestrator actions are recorded in the audit trail. | `server.js` pipeline executor · `runs.plan_summary`, `decisions` |
| B3 | **Web Research** (branch) | Track worker `web`: market scan / tooling / benchmark findings. Runs in parallel with the other two; every finding persisted per track with seq + source. | `findings(track='web')` · UI Stage 3 card |
| B4 | **Files** (branch) | Track worker `files`: corpus indexing, schema extraction, data-quality flags. | `findings(track='files')` · UI Stage 3 card |
| B5 | **Business Logic** (branch) | Track worker `business`: process mapping, automation candidates, ROI/risk modeling. | `findings(track='business')` · UI Stage 3 card |
| B6 | **ModelScope hub: LLM/NLP, Speech, Vision, Multimodal, Embedding/specialist** | Model hub with all five categories from the blueprint box, real ModelScope model IDs. Orchestrator pre-selects 6 slots (2 per track) marked IN USE; strategist can override any slot and recompile. Reassignment validated against slot category and persisted. | `model_slots` table · `PATCH /api/runs/:id/models` · UI Stage 4 |
| B7 | **AI Transformation Brief** | 8-section markdown brief (Exec Summary, Current State, Opportunity Map per track, Model Stack table, Roadmap, Risks, KPIs, Sign-off block) generated from findings + selected models; rendered in-app; copy/download as `.md`; every regeneration stored as a revision. | `briefs` table · `POST /api/runs/:id/recompile` · `GET /api/runs/:id/brief.md` |
| B8 | **Human Approval** (terminal gate) | Pipeline halts at `awaiting_approval`. Approve → named sign-off closes the run; Request changes → feedback folded back into a new revision; Reject → run rejected/archived. Full timestamped audit trail with actor attribution. | `runs.status` state machine · `decisions` · UI Stage 6 |

## 2. Blueprint data model

```
runs        (id, goal, industry, constraints, criteria, status,
             current_stage, plan_summary, revision, signer, approved_at, …)
findings    (run_id, track[web|files|business], seq, content, source)
model_slots (run_id, slot_key[track:idx], category, model_id, role)
briefs      (run_id, revision, markdown, note, created_at)
decisions   (run_id, actor, action, created_at)
settings    (key, value)          -- live-mode provider config
```

## 3. Supporting features (required by the app contract, not in the diagram)

- **Persistence**: everything above is stored in SQLite (`data/studio.db`) via Node's built-in `node:sqlite` — survives restarts; no in-memory-only state.
- **Runs history**: every strategist run is listed and retrievable (`GET /api/runs`).
- **Live execution visibility**: server executes the pipeline stage-by-stage; UI polls `GET /api/runs/:id` and renders progress from real server state.
- **Provider wiring (optional)**: settings for xAI (Grok) + ModelScope keys; masked on read. Demo mode works with zero keys.

## 4. Ambiguities & resolutions (flagged before build)

| Ambiguity | Resolution |
|---|---|
| No deployment/auth specified | Local staging server, prototype-grade (no login) — per goal brief default. |
| Model IDs not specified | Illustrative ModelScope catalog used; editable in `server.js` `CATALOG`. |
| Provider keys | Optional; demo mode is the default and fully functional offline. |
| "Parallel" tracks | Server launches the three workers concurrently (`Promise.all`), findings interleave as they complete. |

## 5. State machine (Human Approval gate)

```
running ──▶ awaiting_approval ──approve──▶ approved (closed)
                │  ▲    └─reject───▶ rejected (archived)
                └──┴──request-changes── new revision, brief regenerated
```
